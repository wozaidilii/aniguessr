# Anime travel planner

Open `/{zh|zh-tw|ja|en}/pilgrimage/planner`. The shared navigation and each anime, area and spot detail page link to it.

## Using the planner
1. Choose anime/places to generate suggested visits, or choose route mode and add city/place anchors in travel order.
2. Set days, transport, pace, optional start date, discovery radius and interests.
3. Add anime discoveries and curated sightseeing, food or onsen stops. Edit visit durations directly in the schedule. In anime mode move visits up/down; in route mode reorder the route anchors.
4. Review long transfers, over-budget days and unscheduled stops. Open each leg in Google Maps to confirm actual transport.
5. Save the local draft, copy a share link, download a text itinerary, or print it.
6. Read matched guides with publisher/language/verification information. Copy the guide list, or prepare and edit an English question before posting it yourself to the linked travel forum.

No account, database migration, new package or paid routing key is required. The compact pilgrimage catalog is generated by `npm run data:build-pilgrimage-seo` (also part of the production build).

## Data and estimates
- Existing catalog coverage is global. Initial curated travel ideas focus on Tokyo, Shonan, Hakone, Kyoto/Uji, Hida, Arima and Dogo. Other areas still have local search links.
- `src/lib/travel/catalog.ts` contains 10 station hubs, 16 curated experiences and 5 starter routes. Use stable IDs, all four languages and official visitor-information links for new records.
- Route calculations are deterministic geographic heuristics. They do not resolve roads, railways, ferries, opening hours, live prices or hotel availability.
- Each selected anime contributes up to 6 spatially separated automatic visits in a 50km local cluster; nearby frames of explicit same-work visits are not duplicated. Add remote or additional spots explicitly. Explicit selections remain in the itinerary or the visible unscheduled list.
- Geographic ordering includes bounded backtracking improvement. Transport estimates use cumulative urban/intercity segments and never decrease when distance increases; they are still not live journey times.
- A local day includes a one-hour meal/rest allowance. Long transfers are estimates and may need an overnight stay or separate travel day.
- The route corridor uses great-circle line segments. Its distance is not driving detour distance. Site-featured anime are prioritized in discoveries; this is an editorial list, not a popularity measurement.

## Klook
`src/server/data/travel-klook.ts` reuses the existing Klook URL builder and destination targets. Verified destination URLs include Tokyo, Kamakura, Kyoto, Osaka and Japan, with a general Klook fallback for other countries.

With existing `AFFILIATE_ENABLED=true` and `KLOOK_AFFILIATE_ID` configured, planner links use the affiliate redirect, sponsored rel and disclosure. Without those settings they remain usable direct destination links. The legacy spot-page allowlist is unchanged. A destination link is not a claim that a specific temple, restaurant or bath is bookable on Klook.

## Storage and sharing
Drafts use `aniguessr_travel_draft_v1` in localStorage. The URL fragment encodes a bounded, validated version-1 state and is not sent as part of the HTTP request. Anyone with the full link can preview the selections. Opening a shared or contextual trip preserves the saved draft until the user edits or explicitly saves; use Return to saved trip to leave the preview. Language changes preserve the preview, and Undo restores up to 20 edits in the current session. Invalid entries preserve and display a valid saved trip when available. Clearing browser storage removes local drafts; keep a share link or export for portability.

## Professional reading and community interaction
`src/lib/travel/guides.ts` contains 11 reviewed source links for Tokyo, Shonan, Hakone, Kyoto/Uji, Osaka, Hida and Dogo. Sources include Klook's editorial blog, japan-guide.com, Odakyu, Hakone Navi and official destination/operator pages. Cards identify the actual original language and source type; localized card titles do not imply translated source articles.

Recommendations match scheduled destinations and selected interests, cover multiple regions before adding extra cards, and retain source links in copied/exported/printed trips. Ranking does not use affiliate revenue. `regions.ts` defines conservative coverage circles; outside this coverage, the UI shows the coverage gap instead of assigning arbitrary places to Japan.

The community tool creates an editable English itinerary question for the public japan-guide.com forum. Exact dates, coordinates and private trip links are omitted. Copying text does not post it; users follow the forum's own account and posting rules. No automatic email, external message or licensed article feed is configured.

Klook's [affiliate program](https://affiliate.klook.com/home) supports a partner discussion. Its publicly reviewed [API integration process](https://klook.gitbook.io/openapi/getting-started/integration-process) describes supplier/reservation-system integration, not an open blog/community API. A future live content or booking feed needs the appropriate partner contract, credentials, attribution and refresh terms. The typed guide catalog is the ingestion boundary for any later authorized feed; keep credentials server-side.

## Validation
Run `npm run check`, `npm test -- src/lib/travel src/server/data/travel-klook.test.ts src/lib/site-nav.test.ts src/lib/same-place-groups.test.ts src/lib/player-session.test.ts`, and `npm run build`.
When no database configuration is available locally, the project's existing `SKIP_ENV_VALIDATION=1` flag allows checks/build; the planner itself does not query the database.
