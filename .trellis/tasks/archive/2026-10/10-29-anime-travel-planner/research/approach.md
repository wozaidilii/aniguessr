# Planner implementation research

- Existing compact navigation catalog is generated by `scripts/build-pilgrimage-seo-data.mjs`. `loadNavCatalog` retries failed requests; work IDs are canonicalized at build time. Reuse browser-side data instead of sending the full SEO index in RSC props.
- Existing Klook targets live in `data/affiliate-klook-targets.json`; wrappers in `src/lib/affiliate/urls.ts`. `AFFILIATE_ENABLED` and `KLOOK_AFFILIATE_ID` remain server-only. Existing page allowlist behavior remains unchanged; planner gets its own curated link map using the shared wrapper.
- Google Maps official URLs: https://developers.google.com/maps/documentation/urls/get-started . Directions use api=1, origin, destination, travelmode; mobile waypoint limits differ. Use per-leg URLs, which also work for transit and do not silently drop intermediate stops.
- Official destination sources checked 2026-10-29: https://www.japan.travel/en/destinations/kanto/kanagawa/kamakura-and-around/ ; https://www.japan.travel/en/destinations/kanto/kanagawa/hakone-and-around/ ; https://www.hakoneyuryo.jp/english/ ; https://kyoto.travel/en/areas/central/ ; https://www.gotokyo.org/en/index.html ; https://www.japan.travel/en/spot/2032/ ; https://visitgifu.com/see-do/takayama-historical-district/ ; https://www.hida.jp/english/touristattractions/4001419/4000090.html . Store descriptions as short editorial ideas, with approximate visit durations and source URLs, not live claims.
- Planning conventions: distinguish hard selected stops from auto suggestions; preserve route anchor order; make candidate limits and unscheduled stops visible; include breaks in budgets; never label straight-line estimates as road distance or real travel time.
- Expansion: local drafts/share/export now; later authenticated trip libraries and routing adapters. Edge cases include remote anime locations, duplicate coordinates, zero-length segments, corrupt share links, unavailable map tiles and storage denial.
